Mental Model

Python simplifies syntax by treating code structure as visual hierarchy

How your JavaScript/TypeScript concepts map to Python's execution and design philosophy

1. Syntax & Blocks Readability

No curly braces or semicolons. Indentation is grammar.

Python
if is_ready:
    process_item(x)
JavaScript / TS
if (isReady) {
  processItem(x);
}
Rule: 4 spaces indentation is the universal Python standard.
2. Type System Dynamic & Strong
  • Dynamic: Types checked at runtime. Variables bind to any object.
  • Strongly Typed: Python will NOT implicitly coerce "4" + 2 (throws TypeError).
  • Type Hints: Optional annotations (like TypeScript, but ignored at runtime).
JS Gotcha: Python rejects silent coercion like "5" - 2.
3. Tooling & Scope Runtime
  • uv: High-performance package & venv manager (replaces npm + nvm + venv).
  • Naming: snake_case for functions/vars, PascalCase for classes.
  • Scope: Python has function & global scope, but no block scope (variables leak past if/for).
Philosophy: "Explicit is better than implicit."

Cheatsheet • Variables & Types

Python binds names to objects directly without declarations like let or const

Variables are object references with dynamic reassignment and optional type annotations

Core Syntax & Value Binding Reference Model 
# Direct assignment (no let/const/var)
name = "Bruce"             # str
count = 42                 # int (arbitrary precision)
price = 99.95              # float
is_active = True           # bool (Capitalized True/False)
payload = None             # NoneType (like null)

# Optional Type Annotations (PEP 484)
username: str = "alex"
age: int = 30
is_admin: bool = False
Key Insight: Variable names in Python are pointers/labels on memory objects.
JS/TS Comparison & Critical Gotchas Watchout
  • No const keyword: Python conventions use ALL_CAPS (e.g. MAX_RETRIES = 5) to signal constants, but it's not enforced by the runtime.
  • No undefined: Python only has None. Accessing an unassigned variable raises NameError.
  • Boolean Casing: Must be True and False with capital letters.
JS / TS
let x = null;
const isOk = true;
Python
x = None
IS_OK = True

Clean text manipulation with f-strings, splitting, joining, and case utilities

f-Strings & Essential Methods Syntax & Ops 
s = "  Python Training  "

s.strip()            # -> "Python Training"

Cheatsheet • Tuples

Tuples represent immutable records and multi-value returns

Lightweight, fixed sequences used for data grouping, dictionary keys, and unpacking

Syntax & Unpacking Fixed Records 
# Defining tuples (parentheses or comma)
point = (10, 20)
http_response = (200, "OK", {"content-type": "json"})
single = (42,)   # Trailing comma required for 1-tuple

# Clean Unpacking (Destructuring)
status_code, status_msg, headers = http_response

# Returning multiple values from a function

    return "alex", "admin"  # Implicit tuple

When to Use: Tuple vs List Decision Framework
  • Use Tuples when: The data has a fixed structure/schema (e.g. (latitude, longitude), database row records).
  • Use Lists when: The data is a homogeneous, growable collection of items.
  • Hashability: Because tuples are immutable, they can be used as Dictionary keys and Set elements (Lists cannot!).
JS Comparison: Similar to TypeScript const point: readonly [number, number] = [10, 20]; but enforced at Python runtime.

Cheatsheet • Sets

Sets provide O(1) membership checks and mathematical collection algebra

Unordered collections of unique elements with native union, intersection, and difference

Syntax & Set Algebra Operations 
dev_skills = {"Python", "TypeScript", "Docker"}
req_skills = {"Python", "FastAPI", "SQL"}

# Set Operations
both = dev_skills & req_skills      # Intersection -> {"Python"}
all_s = dev_skills | req_skills     # Union -> all unique skills
missing = req_skills - dev_skills   # Difference -> {"FastAPI", "SQL"}

# Fast Deduplication
tags = ["bug", "ui", "bug", "auth"]
unique_tags = list(set(tags))       # -> ['bug', 'ui', 'auth']
Key Rules & JavaScript Set Map Best Practices
  • Empty Set Gotcha: {} creates an empty Dictionary! Always use set() for an empty set.
  • Lookup Speed: "Python" in dev_skills is O(1) average time (hash table backed). Checking a list is O(N).
  • Unordered: You cannot index a set (my_set[0] raises TypeError).
JS Set
const s = new Set([1, 2]);
s.has(1);
s.add(3);
Python Set
s = {1, 2}
1 in s
s.add(3)

Cheatsheet • Dictionaries

Dictionaries are high-performance key-value hash maps with safe access methods

Direct counterpart to JavaScript POJOs and Map objects, maintaining insertion order

Core Operations & Safe Access API 
user = {
    "id": 101,
    "name": "Alex Rivera",
    "role": "Engineer"
}

# Safe retrieval with fallback default
role = user.get("role", "Guest")
dept = user.get("department", "Engineering") # No error!

# Updating and Merging
user["status"] = "Active"
user.update({"country": "IN", "tier": 1})

# Iterating keys and values cleanly
for key, value in user.items():
    print(f"{key} -> {value}")

  • KeyError: Accessing missing keys with brackets (user["missing"]) throws a fatal KeyError (unlike JS returning undefined). Always use .get().
JS Gotcha: Never use user.missing_prop or user['missing'] assuming it returns None. Use user.get('missing_prop')!

Cheatsheet • Sequences

Negative indices and slicing syntax [start:stop:step] extract sub-sequences cleanly

Universal slicing mechanics working seamlessly across Strings, Lists, and Tuples

The Slicing Formula: items[start:stop:step] Syntax 
items = ["A", "B", "C", "D", "E", "F"]
# Index:   0    1    2    3    4    5
# Neg:    -6   -5   -4   -3   -2   -1

items[0]        # -> "A" (First element)
items[-1]       # -> "F" (Last element, no .at(-1) required)
items[1:4]      # -> ['B', 'C', 'D'] (Stop index is EXCLUDED)
items[:3]       # -> ['A', 'B', 'C'] (First 3 elements)
items[-2:]      # -> ['E', 'F'] (Last 2 elements)
items[::2]      # -> ['A', 'C', 'E'] (Every 2nd item)
items[::-1]     # -> ['F', 'E', 'D', 'C', 'B', 'A'] (Reversed copy)
Memory Behavior & Bounds Safety Safety Rules
  • Safe Slicing: Slices never raise IndexError even if indices exceed bounds (e.g. items[0:999] cleanly returns all elements).
  • Index vs Slice: Direct indexing out of bounds (items[10]) throws IndexError.
  • Shallow Copy: clone = items[:] produces a fast shallow copy of the entire list.
JS Array
arr[arr.length - 1]
arr.slice(1, 4)
[...arr].reverse()
Python
arr[-1]
arr[1:4]
arr[::-1]

Cheatsheet • Functions

Functions support explicit keyword arguments and default values

First-class callables, flexible parameter passing, and the infamous mutable default argument trap

Definition & Keyword Arguments Flexibility 
def create_task(title: str, priority: str = "Normal", tags: list = None) -> dict:

NEVER write: def add(item, lst=[])

Comprehensions, enumerate, and zip express data transformation declaratively

Replacing imperative loops and .map()/.filter() chains with concise Pythonic primitives

List & Dict Comprehensions Transformations

Gotchas & Best Practices

Top 4 traps JavaScript developers encounter when writing Python

Anticipate these subtle differences to write bug-free Python code immediately

1. Reference Copy vs Object Mutation

Assigning a list/dict to a new variable copies the pointer, not the data. 

a = [1, 2, 3]
b = a          # Aliasing pointer!
b.append(4)    # a is now [1, 2, 3, 4]
c = a.copy()   # True shallow copy
2. Notebook Out-of-Order Execution

Jupyter executes cells in the order you run them, not top-to-bottom.

Rule: Always run "Restart Kernel & Run All Cells" to ensure reproducibility.
3. Identity (is) vs Equality (==)

== tests if contents are equal. is tests if it's the exact same memory address. 

x = [1, 2]; y = [1, 2]
x == y   # -> True (same values)
x is y   # -> False (different memory addresses)
4. Scope Leaks in Blocks

Python has no block scoping for if, for, or while. 

if True:
    temp_val = "Hello"
print(temp_val)  # Works! temp_val leaked into scope
