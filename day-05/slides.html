A real application needs somewhere reliable to persist structured state

Replacing transient in-memory arrays and flat files with ACID relational storage

Structured tables with primary keys, unique constraints, and atomic transactions.

Database Fundamentals

SQLite is a serverless, self-contained, single-file database engine

Why SQLite is the world's most deployed SQL database for desktop, mobile, and small services

How SQLite Works Internally Architecture
Python Process (FastAPI App)
  ↓ Calls built-in C-library bindings
sqlite3 Standard Module
  ↓ Direct file I/O & in-process memory locks
app_data.db (Single binary file on disk!)
Key Feature: Backing up or transferring your entire database is as simple as copying the .db file!
When to Use: SQLite vs PostgreSQL Decision Guide
  • Use SQLite for: Prototyping, CLI tools, local apps, small web APIs (<100k daily requests), testing suites.
  • Move to PostgreSQL when: You have distributed multi-server deployments, high concurrent write throughput, or advanced row-level replication.
Clean Code: Because we use standard SQL queries, transitioning to Postgres later requires zero changes to your API routes!

Cheatsheet • Python sqlite3

Python's sqlite3 module manages connections, cursors, and row factories

Setting conn.row_factory = sqlite3.Row to access columns like Python dictionaries

Connection & Dictionary Row Factory API
import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).parent / "app.db"

def get_db_connection():
    conn = sqlite3.connect(DB_PATH)
    # Enables dictionary-like column access: row["title"]
    conn.row_factory = sqlite3.Row
    return conn

# Safe query execution
with get_db_connection() as conn:
    cursor = conn.cursor()
    cursor.execute("SELECT id, title FROM tasks WHERE id = ?", (1,))
    row = cursor.fetchone()
    if row:
        print(f"Task #{row['id']}: {row['title']}")
Key sqlite3 Mechanics Rules
  • `conn.commit()`: Saves changes permanently to disk. Wrapping in with conn: automatically commits upon successful block exit!
  • `cursor.lastrowid`: Returns the auto-incremented integer ID generated by the last `INSERT`.
  • `cursor.fetchall()`: Returns all matched rows as a list.

Security Critical • OWASP #1

NEVER concatenate raw strings into SQL queries: Always use ? placeholders

How string formatting leads to catastrophic SQL injection and how parameterized queries prevent it

The Dangerous SQL Injection Vulnerability Never Do This
# ❌ VULNERABLE: Direct f-string formatting
user_search = "'; DROP TABLE tasks; --"
query = f"SELECT * FROM tasks WHERE title = '{user_search}'"

cursor.execute(query)
# Executes: SELECT * FROM tasks WHERE title = ''; DROP TABLE tasks; --'
# Database table is completely destroyed!
The Secure Solution: Parameterized Placeholders Secure Standard
# ✅ SECURE: Pass parameters as a separate tuple
cursor.execute(
    "SELECT * FROM tasks WHERE title = ?",
    (user_search,)  # Passed as tuple parameter
)
# SQLite driver treats user_search strictly as literal data!
Rule: The query string itself must NEVER contain user variables. Always pass values via the tuple parameter argument.

Database Architecture

Isolating schema creation and connections in database.py

Creating reusable connection helpers and automatic table initialization on startup

The `app/database.py` Module Code
import sqlite3
from pathlib import Path

DB_FILE = Path(__file__).resolve().parent / "tasks.db"

def get_db():
    conn = sqlite3.connect(DB_FILE)
    conn.row_factory = sqlite3.Row
    return conn

def init_db():
    with get_db() as conn:
        conn.execute("""
        CREATE TABLE IF NOT EXISTS tasks (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            title TEXT NOT NULL,
            description TEXT,
            priority TEXT DEFAULT 'Normal',
            completed INTEGER DEFAULT 0,
            tags TEXT DEFAULT '[]',
            created_at TEXT NOT NULL
        );
        """)
Lifespan Startup in FastAPI Lifecycle
from contextlib import asynccontextmanager
from fastapi import FastAPI
from app.database import init_db

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Runs ONCE when API boots up
    init_db()
    yield

app = FastAPI(lifespan=lifespan)
Startup Hook: Tables are automatically created if they don't exist before accepting any HTTP requests.

Full Stack System

The Complete End-to-End Request Architecture

Tracing a POST request from the frontend UI all the way to persistent disk storage

The Request Pipeline 6-Step Flow
1. Frontend Client (React / Fetch)
  POST /tasks {"title": "Deploy API", "priority": "High"}
2. FastAPI Router (app/main.py)
  Matches endpoint and delegates to service
3. Pydantic Validation (app/models.py)
  Validates TaskCreate schema constraints
4. Service Layer (app/services.py)
  Executes SQL INSERT query via app/database.py
5. SQLite Storage (app/tasks.db)
  Commits row to disk, returns lastrowid
6. JSON Response (HTTP 201 Created)
Key Architectural Advantages Decoupling
  • Zero SQL in Routes: Route functions never touch SQL strings directly.
  • Type-Safe Boundary: Data entering and exiting the service is strictly structured via Pydantic models.
  • Independent Layers: The database layer, service layer, and HTTP layer can each be tested in isolation.

Cheatsheet • Testing

Automated testing with pytest and FastAPI's TestClient

Writing readable unit and integration test functions without complex test runners

Writing Tests with `pytest` tests/test_api.py
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_root_health():
    res = client.get("/")
    assert res.status_code == 200
    assert res.json()["status"] == "online"

def test_create_and_get_task():
    # 1. Create
    create_res = client.post(
        "/tasks",
        json={"title": "Write pytest suite", "priority": "High"}
    )
    assert create_res.status_code == 201
    task_id = create_res.json()["id"]

    # 2. Fetch
    get_res = client.get(f"/tasks/{task_id}")
    assert get_res.status_code == 200
    assert get_res.json()["title"] == "Write pytest suite"

Engineering Excellence

What separates prototype demos from enterprise Python applications

The 5 key engineering practices to implement when taking Python services into production

Production Readiness Checklist Checklist
  • 1. Environment Configuration: Store API keys and database URLs in environment variables (never hardcoded in source code).
  • 2. Structured Logging: Replace print() statements with Python's standard logging module or JSON loggers.
  • 3. Database Migrations: Use migration tools (like Alembic) when schemas evolve in production databases.
  • 4. Connection Limits: Set connection pools and timeouts on external database and HTTP calls.
  • 5. Automated Testing: Maintain CI/CD pipelines running pytest and linting via ruff.
The Enterprise Python Stack Production Standard
Package Manager: uv
Web Framework: FastAPI + Uvicorn
Data Validation: Pydantic v2
Database: PostgreSQL / SQLite + SQLAlchemy
Testing & Linting: pytest + ruff
Containerization: Multi-stage Docker
