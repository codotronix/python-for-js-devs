# EY Executive Presentation Visual Guide (Derived from Reference Deck Analysis)

> **Purpose**
>
> This document captures the visual language observed in a classic EY
> executive presentation deck. It is intended as reusable guidance for
> AI agents or designers creating new EY-style thought leadership
> presentations.
>
> **Important:** This is **not** an official EY design specification. It
> is an inferred design system based on visual analysis and should be
> treated as guidance rather than strict branding rules.

------------------------------------------------------------------------

# 1. Design Philosophy

The deck should communicate **executive thinking**, not artistic
ability.

Primary goals (highest priority first):

1.  Immediate comprehension
2.  Executive readability
3.  Strong business storytelling
4.  Visual consistency
5.  Modern appearance

Every visual element should help explain a business concept.

Avoid decorative graphics.

------------------------------------------------------------------------

# 2. Overall Tone

The presentation should feel:

-   Executive
-   Premium
-   Confident
-   Minimal
-   Structured
-   Technology-oriented
-   Consulting quality

Never feel:

-   Busy
-   Academic
-   Sales-heavy
-   Marketing brochure
-   Startup pitch deck
-   Futuristic for the sake of looking futuristic

------------------------------------------------------------------------

# 3. Color System

Primary Background

-   Very dark charcoal
-   Near-black

Primary Text

-   White

Primary Accent

-   EY Yellow

Supporting Text

-   Light grey

Borders / Secondary Lines

-   Medium grey

Use color sparingly.

Yellow should guide attention---not dominate the slide.

------------------------------------------------------------------------

# 4. Typography

## Headlines

Characteristics:

-   Large
-   Bold
-   Short
-   Business conclusion rather than topic

Example:

Good:

> FDEs compress enterprise delivery by eliminating decision latency.

Avoid:

> Forward-Deployed Delivery

The title should already communicate the takeaway.

------------------------------------------------------------------------

## Body Text

Keep concise.

Ideal:

20--50 words.

Maximum:

\~80 words.

Prefer:

-   3 bullets
-   4 bullets

Avoid:

-   long paragraphs
-   dense reading

------------------------------------------------------------------------

# 5. Layout Principles

Use a clear hierarchy.

Typical layout:

Headline

↓

Main visual

↓

Supporting observations

↓

Source / footer

Maintain generous whitespace.

Never attempt to fill every corner.

------------------------------------------------------------------------

# 6. Visual Hierarchy

Each slide should have:

ONE dominant focal point.

Examples:

-   one diagram
-   one chart
-   one framework
-   one matrix

Do NOT place several competing visuals.

The audience should know where to look in under two seconds.

------------------------------------------------------------------------

# 7. Executive Storytelling

Each slide answers ONE question.

Examples:

Why does delivery need to change?

Who is an FDE?

How does an FDE work?

Why does ecosystem matter?

Where should FDE be used?

Every slide should communicate a complete idea.

------------------------------------------------------------------------

# 8. Preferred Slide Structures

Preferred layouts:

## Option A

Headline

Large Diagram

Executive Summary

Three Insights

------------------------------------------------------------------------

## Option B

Headline

Left: Visual

Right: Key observations

------------------------------------------------------------------------

## Option C

Headline

Top Framework

Bottom Interpretation

------------------------------------------------------------------------

Avoid:

Multiple unrelated visuals.

------------------------------------------------------------------------

# 9. Diagram Philosophy

Prefer original conceptual frameworks over decorative graphics.

Recommended diagrams:

-   Capability Wheels
-   Flywheels
-   Layered Architectures
-   Journey Maps
-   Operating Models
-   Ecosystem Networks
-   Decision Matrices
-   Lifecycle Loops
-   Maturity Curves

Avoid generic SmartArt.

Each diagram should explain an original business idea.

------------------------------------------------------------------------

# 10. Images

Photography should support---not dominate.

Use:

-   technology
-   collaboration
-   engineering
-   digital transformation

Apply subtle dark overlays for readability.

Avoid excessive stock-photo aesthetics.

------------------------------------------------------------------------

# 11. Iconography

Icons should be:

-   Simple
-   Consistent
-   Minimal

Do not mix:

-   Flat
-   3D
-   Filled
-   Outline

Choose one style.

------------------------------------------------------------------------

# 12. Data Visualization

When charts are necessary:

-   Clear labels
-   Limited colors
-   Highlight only key information

The chart supports the conclusion.

The title states the conclusion.

------------------------------------------------------------------------

# 13. Visual Rhythm

Alternate slide types.

Example:

Title

↓

Framework

↓

Architecture

↓

Journey

↓

Matrix

↓

Flywheel

↓

Network

↓

Roadmap

This creates presentation rhythm.

------------------------------------------------------------------------

# 14. White Space

Whitespace is intentional.

Do not fear empty areas.

Executive decks breathe.

------------------------------------------------------------------------

# 15. What Makes an EY Slide Feel Like EY

The visual identity comes from:

-   Strong headline
-   Clear hierarchy
-   Restrained colors
-   Logical layouts
-   Business-first thinking
-   Confident simplicity

Not from decorative effects.

------------------------------------------------------------------------

# 16. Modernization Strategy

For AI-native topics (such as FDE), preserve EY's executive style while
modernizing the visuals.

Replace bullet-heavy slides with:

-   Framework diagrams
-   System maps
-   Operating models
-   Lifecycle visuals
-   Architecture illustrations

The deck should feel like:

"Classic EY executive communication powered by modern systems thinking."

# 18. Golden Rules for Any AI Agent

Before generating a slide, verify:

-   Does the title communicate the conclusion?
-   Is there only one main visual?
-   Can the slide be understood within five seconds?
-   Does every shape explain something?
-   Is the slide free from unnecessary decoration?
-   Is whitespace preserved?
-   Would this look comfortable in front of a CIO or CTO?
-   Does the slide prioritize thinking over visual complexity?

If every answer is YES, the slide is likely aligned with this guide.
