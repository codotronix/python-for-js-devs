Framework Architecture

FastAPI combines Uvicorn, Starlette, and Pydantic into a unified engine

Understanding the tripartite architecture powering modern Python web services

The Three Pillars Components
1. Uvicorn (ASGI Web Server)
Lightning-fast ASGI server implementation (like Node.js http server or Bun).
2. Starlette (Routing & HTTP Toolkit)
Provides core routing, middleware, WebSocket support, and request/response life cycle.
3. Pydantic (Data Validation & Schemas)
Parses, validates, and serializes all JSON payloads and generates OpenAPI specifications.
Installation & Launch CLI Workflow
# 1. Install FastAPI and Uvicorn server via uv
$ uv add "fastapi[standard]"

# 2. Run the development server with live reload
$ uv run fastapi dev app/main.py

# Or using standard uvicorn command:
$ uv run uvicorn app.main:app --reload --port 8000
URL: Live API at http://localhost:8000 | Docs at http://localhost:8000/docs.

Cheatsheet • First Endpoint

Defining API endpoints using decorators: @app.get() and @app.post()

Creating the application instance, returning dictionaries as JSON, and automatic OpenAPI docs

Minimal API Application app/main.py
from fastapi import FastAPI, status

app = FastAPI(
    title="Task Manager API",
    version="1.0.0",
    description="Modern Task API for full-stack integration"
)

@app.get("/")
def root():
    # Dictionaries are automatically serialized to JSON!
    return {"status": "online", "version": "1.0.0"}

@app.get("/health", status_code=status.HTTP_200_OK)
def health_check():
    return {"health": "healthy", "timestamp": "2026-08-27T12:00:00Z"}
Express.js vs FastAPI Comparison
Express.js (Node)
app.get("/health", (req, res) => {
res.status(200).json({
health: "healthy"
});
});
FastAPI (Python)
@app.get("/health")
def health_check():
return {
"health": "healthy"
}
Key Advantage: In FastAPI, returning a dictionary automatically sets Content-Type: application/json and 200 OK.

Cheatsheet • Routing

Path parameters and query parameters are declared directly as function arguments

FastAPI automatically coerces types (e.g. string to int) and validates query defaults

Path & Query Parameters Syntax
# 1. Path Parameter: Declared in path template {task_id}
@app.get("/tasks/{task_id}")
def get_task(task_id: int):
    # If caller passes "/tasks/abc", FastAPI returns 422 immediately!
    return {"task_id": task_id, "title": f"Task #{task_id}"}

# 2. Query Parameters: Any argument NOT in path template
@app.get("/tasks")
def list_tasks(
    status: str = "all",        # Default "all"
    limit: int = 10,           # Default 10
    completed: bool | None = None # Optional bool filter
):
    return {"status": status, "limit": limit, "completed": completed}
Parameter Classification Rules Rules
  • Path Parameter: If a function parameter name matches a {param} in the URL path, it is extracted from the URL path.
  • Query Parameter: If a parameter has a primitive type (str, int, bool) and is NOT in the path, it is parsed from query strings (?limit=20).
  • Request Body: If a parameter is typed as a Pydantic BaseModel, it is parsed from the JSON body!

Cheatsheet • Pydantic v2

Pydantic BaseModel guarantees runtime type safety and parsing

Defining request payloads that validate incoming JSON and reject malformed requests with HTTP 422

Defining Schemas with BaseModel Schemas
from pydantic import BaseModel, Field

class TaskCreate(BaseModel):
    title: str
    priority: str = "Normal"
    completed: bool = False
    tags: list[str] = []

@app.post("/tasks", status_code=status.HTTP_201_CREATED)
def create_task(payload: TaskCreate):
    # payload is a validated Pydantic model instance!
    print(f"Creating: {payload.title} (Priority: {payload.priority})")
    return {"id": 101, **payload.model_dump()}
TypeScript Interface vs Pydantic Model Runtime vs Static
TypeScript Interface
interface TaskCreate {
title: string;
priority?: string;
}
// Disappears at runtime!
Pydantic BaseModel
class TaskCreate(BaseModel):
title: str
priority: str = "Normal"
# Enforced at runtime!
Zod Comparison: Pydantic in Python plays the exact role of z.object({ title: z.string() }) in TypeScript.

Cheatsheet • Validation Rules

Field(...) adds constraints, descriptions, and defaults to schemas

Enforcing string lengths, numeric ranges, and regex patterns directly in the model definition

Constraint Rules with Field Validation
from pydantic import BaseModel, Field

class TaskCreateRequest(BaseModel):
    title: str = Field(
        min_length=3,
        max_length=100,
        description="The title of the task",
        examples=["Deploy staging cluster"]
    )
    priority: str = Field(
        default="Normal",
        pattern="^(Low|Normal|High|Urgent)$"
    )
    estimated_hours: float = Field(
        default=1.0,
        gt=0,
        le=80.0
    )
Automatic 422 Error Response Zero Code Error Handling

If a client sends {"title": "ab", "priority": "Invalid"}, FastAPI automatically returns HTTP 422:

      "loc": ["body", "title"],

      "type": "string_too_short"

Cheatsheet • Response Models

response_model filters sensitive fields and documents API responses

Preventing secret data leaks (like passwords or internal hashes) before sending JSON to the client

Separating Request & Response Schemas Pattern
class UserCreate(BaseModel):
    username: str
    email: str
    password: str  # Incoming plain password

class UserResponse(BaseModel):
    id: int
    username: str
    email: str
    # Notice: password is OMITTED!

@app.post("/users", response_model=UserResponse)
def register_user(user_in: UserCreate):
    user_db_record = user_service.create(user_in)
    return user_db_record  # FastAPI filters out password automatically!
Benefits of `response_model` Security
  • Data Masking: Automatic stripping of internal fields not declared in the response model.
  • Swagger Accuracy: OpenAPI documentation displays exact JSON return shape for frontend consumers.
  • Data Conversion: Automatically converts Python Dataclasses and ORM objects into JSON-compliant dictionaries.

Architecture Flow

The Complete FastAPI Request & Response Lifecycle

How HTTP requests flow through validation, controllers, and services to return structured JSON

The 5-Stage Lifecycle Flow
1. HTTP Request from Client (React / Mobile)
  ↓ URL, Headers, JSON Body
2. FastAPI Routing Engine
  ↓ Matches /tasks/{id} and HTTP Method
3. Pydantic Runtime Validation
  ↓ Invalid -> Returns 422 immediately
4. Service Layer Execution
  ↓ Queries memory / SQLite / external API
5. JSON Serialization & Response Model Filtering
Clean Separation of Concerns Architecture
  • Routes (Controllers): Handle HTTP protocol, status codes, and model bindings.
  • Pydantic Models: Handle input parsing, sanitization, and response filtering.
  • Services: Contain domain business logic and database persistence.
Golden Rule: Keep routes thin! Never place heavy database queries or calculations directly inside route functions.

Cheatsheet • Async Routes

Use async def for I/O operations; use def for synchronous CPU work

How FastAPI handles concurrency under the hood between the async event loop and thread pools

Async Route with Async Client Non-Blocking
import httpx

@app.get("/github/{username}")
async def get_github_profile(username: str):
    # Uses non-blocking HTTPX async client
    async with httpx.AsyncClient() as client:
        res = await client.get(f"https://api.github.com/users/{username}")
        if res.status_code == 404:
            raise HTTPException(status_code=404, detail="User not found")
        return res.json()
FastAPI's Dual Execution Strategy Performance
  • When you use async def: FastAPI runs the function directly on the main async event loop. You must await any I/O calls!
  • When you use def (standard sync): FastAPI automatically runs the function in an external worker thread pool so it won't block the event loop.
Watchout: If you write async def but call a blocking synchronous library inside it (like time.sleep or standard SQLite), you will freeze the server!

Cheatsheet • Error Handling

HTTPException returns clean, structured HTTP status codes to the client

Intercepting domain errors and translating them into standard HTTP 404, 400, 401, or 409 payloads

Raising `HTTPException` Error Flow
from fastapi import HTTPException, status
from app.models import TaskNotFoundError

@app.get("/tasks/{task_id}")
def get_single_task(task_id: int):
    try:
        return task_service.get_task(task_id)
    except TaskNotFoundError:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Task with ID {task_id} was not found"
        )
Structured Error JSON Output Client Response

FastAPI automatically formats the exception into a standard JSON payload:

// HTTP 404 Not Found
{
  "detail": "Task with ID 999 was not found"
}
Custom Details: You can pass dictionaries or lists to detail= (e.g. detail={"error_code": "TASK_EXPIRED", "retry": False}).

Project Architecture

Layered architecture: separating routes, schemas, and service logic

A lightweight, maintainable multi-file project layout for real-world production APIs

Project Layout Directory Tree
app/
├── main.py          # FastAPI app & route endpoints
├── models.py        # Pydantic request/response schemas
├── services.py      # Business logic & data access
└── data/tasks.json  # Persistent storage
Why This Structure Wins Benefits
  • Testable: Services can be tested independently of HTTP requests using pytest.
  • Swappable Storage: Changing from JSON file storage to SQLite (Day 5) only changes services.py—route controllers remain untouched!
  • Type Cohesion: Schemas defined in models.py serve as the single source of truth.

Critical Gotchas • Performance

Don't mix blocking synchronous I/O inside async def routes

Why calling synchronous database or HTTP operations in async endpoints degrades concurrency

The Event Loop Blocker Anti-Pattern
# ❌ DANGEROUS: Declared async def, but calls blocking I/O
@app.get("/report")
async def generate_report():
    # Blocking sync call freezes the entire web server!
    time.sleep(3.0)
    return {"report": "ready"}
The Two Correct Options Solutions
# Option A: Use standard `def` (FastAPI uses thread pool)
@app.get("/report")
def generate_report_sync():
    time.sleep(3.0)  # Safe in thread pool!
    return {"report": "ready"}

# Option B: Use true non-blocking async
@app.get("/report")
async def generate_report_async():
    await asyncio.sleep(3.0)  # Non-blocking
    return {"report": "ready"}

Critical Gotchas • Code Design

Avoid placing database queries and business logic inside route functions

Routes should only handle HTTP concerns and delegate domain logic to services

Fat Route Anti-Pattern Poor Maintainability
@app.post("/tasks")
def create_task(task: TaskCreate):
    # Direct file I/O, business validation, ID generation
    with open("tasks.json", "r+") as f:
        data = json.load(f)
        new_id = max(d["id"] for d in data) + 1
        data.append({"id": new_id, **task.model_dump()})
        f.seek(0)
        json.dump(data, f)
    return {"id": new_id}
Thin Route Pattern Clean Architecture
@app.post("/tasks", status_code=status.HTTP_201_CREATED)
def create_task(
    task: TaskCreate,
    response_model=TaskResponse
):
    # Delegate to service layer
    return task_service.create_task(task)
Rule: Keep routes under 10 lines of code.
