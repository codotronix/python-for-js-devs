Why HTTPX Replaced Requests Standard
  • The Legacy Gap: Python's traditional requests library is strictly synchronous and blocking. It cannot be used in modern async backends (like FastAPI).
  • The HTTPX Advantage: Offers an identical clean API, but supports both synchronous (httpx.get) and asynchronous (await client.get) workflows.
  • Strict Timeouts by Default: Automatically enforces default timeouts to prevent hanging sockets.
Standard Rule: For all new Python applications, choose httpx over requests or urllib.

Cheatsheet • HTTP Resilience

raise_for_status() converts 4xx and 5xx responses into catchable exceptions

Building fault-tolerant HTTP integrations with explicit status checks and timeout policies

The raise_for_status() Pattern Error Flow
import httpx

def fetch_resource(url: str) -> dict:
    try:
        res = httpx.get(url, timeout=5.0)
        res.raise_for_status()  # Raises HTTPStatusError if 4xx/5xx
        return res.json()
    except httpx.HTTPStatusError as err:
        print(f"HTTP Error {err.response.status_code}: {err.request.url}")
        return {}
    except httpx.TimeoutException:
        print("Network request timed out")
        return {}
    except httpx.RequestError as err:
        print(f"Connection failure: {err}")
        return {}
Production Best Practices Checklist
  • Always set a timeout: Defaulting to no timeout means network disconnects can hang your application process forever.
  • Distinguish Network vs Status Errors:
    • RequestError = DNS failure, connection refused, offline.
    • HTTPStatusError = Server returned 404, 401, 500, etc.
  • Never catch raw Exception: Catch specific HTTPX errors to allow programming bugs to bubble up.

Async Mental Model

Python Coroutines are unstarted computations; JS Promises start immediately

Understanding the subtle execution differences between JavaScript and Python event loops

JavaScript Promises (Hot / Eager) JavaScript

In JS, calling an async function immediately schedules and starts execution:

// JavaScript
async function fetchData() { ... }

// Starts executing IMMEDIATELY in background!
const promise = fetchData();

// Await just waits for completion
const result = await promise;
Python Coroutines (Cold / Lazy) Python

In Python, calling an async def function creates a coroutine object that does NOTHING until explicitly awaited or scheduled:

async def fetch_data(): ...

# DOES NOT EXECUTE! Returns a coroutine object
coro = fetch_data()

# Only starts running when awaited or passed to gather
result = await coro
Gotcha: Forgetting await in Python does not start background work—it silently leaves the coroutine unexecuted!

Cheatsheet • Async HTTPX

httpx.AsyncClient enables high-throughput asynchronous HTTP

Using async with context managers to handle non-blocking network I/O cleanly

The AsyncClient Pattern Non-Blocking
import httpx
import asyncio

async def fetch_user(username: str) -> dict:
    url = f"https://api.github.com/users/{username}"
    async with httpx.AsyncClient(timeout=10.0) as client:
        response = await client.get(url)
        response.raise_for_status()
        return response.json()

# In scripts: asyncio.run(fetch_user("sumanbarick"))
# In Jupyter: await fetch_user("sumanbarick")
Key Mechanics: async with & `asyncio.run` Lifecycle
  • async with: Asynchronous context manager. Closes TCP sockets and connection pools asynchronously on exit.
  • Entrypoint (asyncio.run): In standalone scripts, asyncio.run(main()) starts the event loop, runs the coroutine, and shuts down the loop cleanly.
JS async/await
async function main() {
const res = await client.get();
}
main();
Python async/await
async def main():
res = await client.get()

asyncio.run(main())

Cheatsheet • Concurrency

asyncio.gather runs multiple asynchronous operations in parallel

Executing hundreds of network requests concurrently on a single thread—Python's Promise.all()

Parallel Fetching Pattern Promise.all
import asyncio
import httpx

async def fetch_repo_stars(client: httpx.AsyncClient, repo: str) -> tuple[str, int]:
    url = f"https://api.github.com/repos/{repo}"
    res = await client.get(url)
    stars = res.json().get("stargazers_count", 0)
    return repo, stars

async def fetch_all_repos(repos: list[str]):
    async with httpx.AsyncClient() as client:
        # Build list of coroutines
        tasks = [fetch_repo_stars(client, r) for r in repos]
        # Execute concurrently!
        results = await asyncio.gather(*tasks)
        return results
Speed Comparison & Behavior Throughput
Sequential (Sync): 10 requests × 200ms = 2.0s
Concurrent (asyncio.gather): 10 requests in ~220ms total!
  • Single-Threaded: No multi-threading overhead or GIL locking issues. The event loop switches tasks while waiting on network sockets.
  • Error Propagation: If one task raises an exception, gather propagates it immediately by default (or use return_exceptions=True).

Concurrency Framework

Async solves I/O latency; multiprocessing solves CPU computation

Knowing when asyncio accelerates your application and when it does not

I/O-Bound Workload (Use Async!) Async Win

The CPU is idle 99% of the time, waiting on external network/disk responses.

  • HTTP REST API calls & microservices
  • Database queries & Redis cache lookups
  • Web scraping and file downloads
  • WebSocket connections and chat servers
Benefit: Handle 10,000+ concurrent connections on minimal RAM.
CPU-Bound Workload (Async Won't Help) CPU Bound

The CPU is actively computing 100% of the time (no waiting).

  • Image/video processing and transcoding
  • Heavy mathematical simulations & cryptography
  • Machine learning model inference
  • Massive JSON serialization of multi-gigabyte arrays
Rule: CPU-bound tasks in Python require multiprocessing or worker queues (Celery/RQ), not asyncio!

Cheatsheet • Iteration Protocol

Iterables can produce iterators; Iterators maintain active state with next()

The underlying protocol that powers Python's for loops and comprehension mechanics

The `iter()` and `next()` Protocol Mechanics
fruits = ["apple", "banana", "cherry"]  # Iterable

# 1. Get Iterator from Iterable
it = iter(fruits)

# 2. Advance iterator step by step
print(next(it))  # -> "apple"
print(next(it))  # -> "banana"
print(next(it))  # -> "cherry"

# 3. Exhausted Iterator raises StopIteration
# next(it) -> raises StopIteration exception
# (for loops catch StopIteration automatically!)
Key Distinctions Definitions
  • Iterable: An object that can return an iterator (has __iter__()). E.g., Lists, Dicts, Tuples, Sets, Strings. Can be iterated repeatedly.
  • Iterator: An object that tracks its current position in a stream (has __next__()). Stateful and single-pass.
JS Comparison: Directly corresponds to JavaScript's Symbol.iterator and Iterator protocol ({ value, done }).

Cheatsheet • Generators

Generators stream items lazily with yield, saving gigabytes of memory

Functions that pause and resume execution, producing values on demand without storing arrays in RAM

Generator Functions with yield Streaming
def paginate_records(page_size: int = 100, max_pages: int = 3):
    for page in range(1, max_pages + 1):
        print(f"--> Fetching page {page} from DB...")
        records = [f"record_{page}_{i}" for i in range(page_size)]
        for r in records:
            yield r  # Pauses and returns item to caller!

# Consuming lazily in a loop
for item in paginate_records(page_size=2, max_pages=2):
    print(f"Processed: {item}")
List vs Generator Expression Memory Win
# 1. List Comprehension (Allocates ALL 1M ints in RAM!)
big_list = [x * 2 for x in range(1_000_000)]  # ~8MB RAM

# 2. Generator Expression (Uses parentheses, computes on demand!)
big_gen = (x * 2 for x in range(1_000_000))  # ~100 BYTES RAM!
Use Cases: Reading 10GB CSV/log files line-by-line, paginating API results, and event stream pipelines.

Critical Gotchas • Async

Forgetting await produces a silent coroutine object instead of data

Why calling async functions without await does not crash immediately, but yields <coroutine object>

The Un-awaited Coroutine Bug Silent Trap
async def get_task_count():
    return 42

# BUG: Forgot 'await'!
count = get_task_count()

print(count)
# Output: <coroutine object get_task_count at 0x1042...>
# RuntimeWarning: coroutine 'get_task_count' was never awaited!
Notebook vs Script Execution Context Environment
  • In Jupyter Notebooks: An event loop is already running. You can use await my_func() directly at the top level of any cell!
  • In Standard Python Scripts: You cannot call top-level await outside a function. You must start the event loop with: 
    if __name__ == "__main__":
    asyncio.run(main())

Critical Gotchas • Event Loop

Synchronous blocking calls freeze the entire async event loop

Never use time.sleep() or synchronous httpx.get() inside an async coroutine

The Blocking Freeze Trap Bottleneck
import time
import asyncio

async def bad_worker(worker_id: int):
    # ❌ FREEZES THE ENTIRE PROCESS FOR 2 SECONDS!
    time.sleep(2)
    print(f"Worker {worker_id} done")

# Running bad_worker with gather will run SERIALLY, not concurrently!
The Non-Blocking Async Solution Correct
async def good_worker(worker_id: int):
    # ✅ Yields control to event loop cooperatively
    await asyncio.sleep(2)
    print(f"Worker {worker_id} done")

# Running 10 good_workers with gather finishes in ~2.0s total!
Rule: In async code, replace time.sleep with await asyncio.sleep, and sync HTTP calls with await client.get.

Critical Gotchas • Generators

Generators are single-pass streams: once consumed, they are empty

Understanding generator exhaustion and why iterating a generator a second time yields nothing

The Exhaustion Trap Single Pass
gen = (x * 2 for x in [1, 2, 3])

# 1. First iteration consumes all values
print("Pass 1:", list(gen))  # -> [2, 4, 6]

# 2. Second iteration: Generator is now EXHAUSTED!
print("Pass 2:", list(gen))  # -> [] (Empty!)
When to Materialize into a List Decision
  • Keep as Generator when: You only iterate over data once (e.g., streaming rows to an API or writing to disk).
  • Convert to List (list(gen)) when: You need to access elements by index (gen[0]), check length (len(gen)), or iterate multiple times.
