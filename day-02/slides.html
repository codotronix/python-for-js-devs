Cheatsheet • OOP Fundamentals

Python classes use explicit self to reference the instance

Constructors (__init__), instance methods, and how self differs from JavaScript's dynamic this

Class Definition & Methods Syntax
class TaskManager:
    def __init__(self, project_name: str):
        # Instance attribute (attached to specific instance)
        self.project_name = project_name
        self.tasks = []

    def add_task(self, task_title: str) -> None:
        self.tasks.append(task_title)

    def count(self) -> int:
        return len(self.tasks)

# Instantiation (no 'new' keyword!)
manager = TaskManager("Platform V2")
manager.add_task("Implement Auth")
print(manager.count())  # -> 1
The self vs this Mental Model Key Takeaways
  • Explicit self: In Python, self must be the first parameter of every instance method definition, but it is passed automatically when calling obj.method().
  • No this binding issues: Unlike JS where this can lose context when passed as a callback, Python method references retain their bound instance!
  • No new keyword: Call the class directly as a function (e.g. TaskManager(...)).
JS Translation: def __init__(self, x): is Python's constructor: constructor(x) { this.x = x; }.

Cheatsheet • Dataclasses

Dataclasses eliminate OOP boilerplate and provide structured domain models

Using @dataclass to automatically generate constructors, string representations, and value comparisons

Clean Model Definition with @dataclass Boilerplate-Free
from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class Task:
    id: int
    title: str
    completed: bool = False
    priority: str = "Normal"
    tags: list[str] = field(default_factory=list)

# Automatic constructor, __repr__, and __eq__
t1 = Task(id=1, title="Write docs", priority="High")
t2 = Task(id=1, title="Write docs", priority="High")

print(t1)       # -> Task(id=1, title='Write docs', ...)
print(t1 == t2) # -> True (Compares values, not memory pointers!)
Why Dataclasses are Superior to Plain Classes Benefits
  • Zero Boilerplate: No need to manually write repetitive def __init__(self, a, b, c): self.a = a....
  • Meaningful String Print: print(task) displays formatted property values instead of obscure memory addresses like <Task object at 0x102...>.
  • Safe Mutable Defaults: Use field(default_factory=list) to ensure every instance receives a unique list.
FastAPI Bridge: In Day 4, Pydantic's BaseModel expands on this exact syntax to add automatic API request validation!

Cheatsheet • File Operations

pathlib.Path provides intuitive, cross-platform filesystem manipulation

Replacing legacy string concatenation with the modern slash operator / and path inspection methods

The pathlib.Path API Modern I/O
from pathlib import Path

# Resolving the directory of the current script
BASE_DIR = Path(__file__).resolve().parent
DATA_DIR = BASE_DIR / "data"             # Uses / for cross-platform joining
DATA_FILE = DATA_DIR / "tasks.json"

# Safe directory creation (mkdir -p equivalent)
DATA_DIR.mkdir(parents=True, exist_ok=True)

# Path properties
print(DATA_FILE.name)       # -> "tasks.json"
print(DATA_FILE.suffix)     # -> ".json"
print(DATA_FILE.exists())   # -> True / False

# Direct text read/write shortcuts for small files
DATA_FILE.write_text('{"status": "ok"}', encoding="utf-8")
content = DATA_FILE.read_text(encoding="utf-8")
Node.js `path` vs Python `pathlib` Comparison
  • The Slash Operator: DATA_DIR / "file.txt" works seamlessly on Windows (\), macOS, and Linux (/).
  • Always anchor to __file__: Relative paths like open("data.json") depend on where you ran the terminal from! Always use Path(__file__).parent.
Node.js path / fs
path.join(__dirname, "data");
fs.existsSync(p);
fs.mkdirSync(p, {recursive:true});
Python pathlib
Path(__file__).parent / "data"
p.exists()
p.mkdir(parents=True, exist_ok=True)

Cheatsheet • Resource Management

The with statement guarantees resource cleanup and prevents leaks

Deterministic file descriptor and connection closing even if unexpected exceptions occur

Context Managers with open(...) Pattern
from pathlib import Path

log_path = Path(__file__).parent / "app.log"

# 1. Writing to a file cleanly (mode="w" or mode="a" for append)
with open(log_path, mode="a", encoding="utf-8") as file:
    file.write("2026-08-27: User authenticated successfully\n")
# File is GUARANTEED closed here!

# 2. Reading line-by-line efficiently
with open(log_path, mode="r", encoding="utf-8") as file:
    for line in file:
        print(f"Log: {line.strip()}")
Why Never Use Manual file.close() RAII Safety
  • Exception Safety: If an unhandled exception occurs inside a with block, Python's runtime guarantees the file handle is closed immediately before propagating the error.
  • Encapsulation: Eliminates boilerplate try ... finally { file.close() } blocks.
  • Universal Concept: Used across Python for database connections, locks, thread pools, and network sessions.
Rule of Thumb: If an object manages an external I/O resource, always consume it within a with block.

Cheatsheet • JSON & Persistence

Python's json module provides intuitive serialization and deserialization

Distinguishing between in-memory string conversion (dumps/loads) and direct file I/O (dump/load)

The Four Core JSON Functions API
import json
from pathlib import Path

data = [{"id": 1, "title": "Review PR", "done": False}]
target_file = Path(__file__).parent / "tasks.json"

# 1. Direct File Save: json.dump (writes to file object)
with open(target_file, "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

# 2. Direct File Read: json.load (reads from file object)
with open(target_file, "r", encoding="utf-8") as f:
    loaded_data = json.load(f)

# 3. String Conversion: json.dumps / json.loads (In-memory)
json_str = json.dumps(data)              # JS: JSON.stringify(data)
parsed_dict = json.loads(json_str)        # JS: JSON.parse(json_str)
Memory Aid: The "s" Rule & JS Comparison Mnemonic
Memory Aid:
• json.loads() / dumps() with an s operates on Strings.
• json.load() / dump() without an s operates on Files.
JavaScript
JSON.stringify(obj, null, 2);
JSON.parse(str);
Python
json.dumps(obj, indent=2)
json.loads(str)

Cheatsheet • Exceptions

Python exception handling uses try / except / else / finally blocks

Structured, granular error interception with explicit exception classes and cleanup logic

Structured Exception Syntax Control Flow
def read_config(file_path: str) -> dict:
    try:
        with open(file_path, "r") as f:
            return json.load(f)
    except FileNotFoundError:
        print(f"Config file not found at {file_path}, using defaults")
        return {"theme": "dark", "retries": 3}
    except json.JSONDecodeError as err:
        print(f"Malformed JSON on line {err.lineno}: {err.msg}")
        raise ValueError("Invalid configuration format") from err
    finally:
        print("Config load attempt completed")
Common Built-In Exception Types Reference
  • ValueError: Right type, but inappropriate value (e.g. int("abc")).
  • KeyError: Accessing a dictionary key that does not exist.
  • TypeError: Operation on an incompatible type (e.g. len(42)).
  • FileNotFoundError: Missing file during filesystem operations.
  • IndexError: Sequence subscript out of range.
JS Comparison: raise ValueError("...") corresponds directly to JavaScript's throw new Error("...").

Cheatsheet • Custom Exceptions

Custom exceptions create clean, expressive application error domains

Inheriting from Exception to distinguish business rule violations from system crashes

Defining & Raising Domain Exceptions Pattern
# 1. Base application exception
class AppError(Exception):
    """Base exception for all application errors."""
    pass

# 2. Specific domain errors
class TaskNotFoundError(AppError):
    def __init__(self, task_id: int):
        self.task_id = task_id
        super().__init__(f"Task with ID {task_id} was not found.")

class DuplicateTaskError(AppError):
    pass

# Raising domain exception
def find_task(task_id: int, tasks: list):
    for t in tasks:
        if t.id == task_id:
            return t
    raise TaskNotFoundError(task_id)
Interception at the Service / API Boundary Handling
try:
    task = find_task(999, active_tasks)
except TaskNotFoundError as err:
    # Clean boundary translation to HTTP 404 in FastAPI
    print(f"Handled error: {err} (ID: {err.task_id})")
  • Self-Documenting Code: Calling code immediately knows which failure states to handle.
  • Payload Attached: Store metadata directly on the error instance (e.g. err.task_id).

Cheatsheet • Decorators

Decorators are higher-order functions that wrap and augment behavior

Understanding the syntax sugar @decorator as func = decorator(func)

How Decorators Work Internally Higher-Order
import functools
import time

def timer(func):
    @functools.wraps(func)  # Preserves original func name & docstring
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"[PERF] {func.__name__} executed in {elapsed*1000:.2f}ms")
        return result
    return wrapper
Applying Decorators with @ Usage
@timer
def process_records(count: int):
    time.sleep(0.05)  # Simulate I/O or work
    return f"Processed {count} records"

# Calling the decorated function normally
msg = process_records(500)
# Prints: [PERF] process_records executed in 50.12ms
JS Comparison: Similar to Higher-Order Components (HOCs) in React or Express middleware wrappers: const withTimer = fn => (...args) => ....

Critical Gotchas • Classes

The mutable class attribute trap: shared state across instances

Distinguishing between class-level variables (shared) and instance-level attributes (isolated)

The Trap: Class-Level Mutable List Dangerous Bug
class BuggyUser:
    # Class attribute (shared by ALL instances!)
    roles = []

u1 = BuggyUser()
u2 = BuggyUser()

u1.roles.append("admin")

# BUG: u2 has "admin" too!
print(u2.roles)  # -> ['admin']
Cause: Attributes defined directly under class belong to the class object, not individual instances!
The Fix: Initialize in `__init__` or `@dataclass` Clean Fix
class SafeUser:
    def __init__(self):
        # Instance attribute (unique per instance)
        self.roles = []

u1 = SafeUser()
u2 = SafeUser()

u1.roles.append("admin")
print(u2.roles)  # -> [] (Completely isolated!)
Dataclass Pattern: In dataclasses, use roles: list[str] = field(default_factory=list).

Critical Gotchas • File Paths

Relative file paths break when scripts are executed from different directories

Why open("data.json") fails in production and how Path(__file__).parent solves it

The Fragile Relative Path Trap Runtime Error
# In app/services.py:
def load_data():
    # Fragile: Looks in current working directory (CWD)!
    with open("data/tasks.json") as f:
        return json.load(f)

# If run from workspace root: works!
# If run from inside app/ or via cron/test: FileNotFoundError!
Root Cause: Relative string paths resolve against os.getcwd(), NOT the file location!
The Robust Pattern: Anchor with `__file__` Production Standard
from pathlib import Path

# Always anchor relative to the current script file
BASE_DIR = Path(__file__).resolve().parent
DATA_PATH = BASE_DIR / "data" / "tasks.json"

def load_data_safe():
    with open(DATA_PATH, "r", encoding="utf-8") as f:
        return json.load(f)
Rule: Always anchor paths relative to Path(__file__).parent.

Critical Gotchas • Error Handling

Broad except Exception: swallows critical syntax and system errors

Catch specific exceptions to prevent masking syntax typos, missing imports, and interrupts

Anti-Pattern: Catching Everything Blindly Dangerous
try:
    user_record = fetch_user_data(user_id)
except Exception:
    # SWALLOWS: NameError, TypeError, KeyboardInterrupt!
    print("Something failed")
    return None
  • If you have a typo (e.g. fetch_usr_data), it silently fails instead of showing a helpful traceback!
Production Pattern: Specific Interception Clean Code
try:
    user_record = fetch_user_data(user_id)
except (UserNotFoundError, TimeoutError) as err:
    print(f"Expected operational failure: {err}")
    return fallback_user()
Best Practice: Only catch exceptions you know how to recover from. Let unexpected programming bugs fail fast.
